# 静态部署方案

本项目不需要后端、数据库、安装命令或构建命令。所有平台都应将仓库根目录作为发布目录。

## 推荐仓库流程

```text
本地修改 -> 浏览器验证 -> Git 提交 -> 推送 main -> 静态平台自动发布
```

建议在正式公开前确认：

- `index.html` 可以正常打开并生成全部 11 个字段。
- 单项重抽与锁定依赖正确。
- 窄屏下没有横向溢出。
- 复制和 JSON 导出在 HTTPS 网站中可用。
- 仓库中不存在 API 密钥、账号凭证或私人文件。

## GitHub Pages

适合公开源码并直接从 GitHub 托管。

1. 在 GitHub 创建空仓库。
2. 将本地 `main` 分支推送到该仓库。
3. 在仓库的 Pages 设置中选择从分支发布。
4. 发布分支选择 `main`，目录选择仓库根目录。

仓库中的 `.nojekyll` 会让 Pages 按普通静态文件处理项目。

## Cloudflare Pages

适合连接 Git 仓库后自动发布。

- 框架预设：无或静态 HTML。
- 构建命令：留空。
- 构建输出目录：仓库根目录。

每次推送到生产分支后，平台会重新部署。

## Netlify 或 Vercel

导入 Git 仓库并使用静态站点设置：

- 安装命令：留空。
- 构建命令：留空。
- 发布目录：`.`。

如果平台要求框架类型，选择静态 HTML 或 Other。

## 什么时候需要后端

只有加入以下功能时才需要服务器或云函数：

- 注册、登录和跨设备存档
- 多人共享或审核角色
- 排行榜、投稿和后台管理
- 调用必须隐藏密钥的第三方或 AI API
- 集中保存生成历史

即使增加后端，静态页面本身仍可继续使用上述平台托管。
