# 数据模型与生成规则

## 设计目标

生成器不是把所有字段独立抽取后简单拼接，而是先生成上游字段，再为下游字段选择兼容数据。

```text
体型 ──────────> 身高与 B/W/H
头发长度 ──────> 发型
染发模式 ──────> 染法 + 协调色组
瞳色模式 ──────> 单色或协调异色组
服装结构 ──────> 服装档案 ──────> 鞋袜与配饰
基础气质 ──────> 社交表达 ──────> 可选萌点
```

## 字段

| 顺序 | 键 | 生成规则 |
|---:|---|---|
| 01 | `name` | 根据中式、日式或西式姓名体系组合 |
| 02 | `body` | 从成年女性体型档案选择描述 |
| 03 | `hairColor` | 纯色，或染法与预先审核的协调色组 |
| 04 | `hairLength` | 从五种长度范围选择 |
| 05 | `hairStyle` | 只从当前长度对应的发型池选择 |
| 06 | `eyes` | 纯色，或从协调异色瞳组合中选择 |
| 07 | `measurements` | 根据体型区间生成相关的身高和 B/W/H |
| 08 | `skin` | 肤色名称、底调和参考色 |
| 09 | `outfit` | 服装结构、风格档案与配色方案 |
| 10 | `finishing` | 从当前服装档案选择鞋、袜和两件不重复配饰 |
| 11 | `personality` | 融合两到三个兼容性格标签 |

## 锁定依赖

锁定下游字段时会同时锁定它的直接上游字段，防止重新生成后产生不一致：

- 锁定发型，同时锁定头发长度。
- 锁定身体数据，同时锁定体型。
- 锁定鞋袜与配饰，同时锁定衣着。

全部解锁不会重新生成数据，只解除保护状态。

## 身体数据

每个体型提供身高、胸围、腰围和臀围的合理区间。生成器在随机取值后继续执行最小差值约束，因此不会把四项当作互不相关的数字。

所有角色固定为成年女性。“娇小”和“少女感”描述的是成年人的体型与视觉气质，不表示未成年年龄。

## 配色

染发和异色瞳不从全部颜色做笛卡尔积随机，而是从人工整理的兼容色组中选择。这样可以避免高概率产生浑浊、刺眼或缺乏主次的组合。

服装档案同样绑定两套配色、鞋类、袜类和配饰池。配饰每次选择两件，且不会重复。

鞋袜配饰采用两层数据：`OUTFITS` 保存每套造型的基础池，`FINISHING_EXPANSIONS` 保存按风格补充的扩充池。页面初始化时按 `style` 合并，因此学院、偶像、洛丽塔、地雷系、原宿、辣妹、机能、森系、复古与通勤元素不会跨风格乱配。当前 23 套档案各包含 4 种鞋、4 种袜类和 7 种配饰，共 345 个池条目。

## 性格融合

性格分为三层：

1. `temperament`：基础气质，例如元气、冷静、傲娇、酷娇。
2. `expression`：社交表达，例如热情健谈、安静慢热、毒舌、坦率。
3. `accent`：可选萌点，例如迷糊冒失、中二、大小姐、努力家。

每个标签包含 `conflicts` 列表。组合时执行双向检查：A 排斥 B 或 B 排斥 A，均视为不可组合。第三层只有在同时兼容前两个标签时才可加入。

## 本地状态

状态使用键 `modern-persona-roller-v1` 保存在 `localStorage`，内容包括：

- 当前生成值与说明文本
- 色板
- 锁定字段
- Roll 次数
- 用户选择的生成模式

这些数据不会自动跨设备同步，也不会发送给服务器。
